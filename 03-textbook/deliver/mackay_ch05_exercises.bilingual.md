# MacKay《Information Theory, Inference, and Learning Algorithms》Ch.05 习题解答（第 1 部分）双语译注

## Exercise 5.8（習題 5.8）　[1, p.104]

**题干原文：** Is C2 uniquely decodeable?

**中文：** 码（code）C2 是否唯一可译码（uniquely decodeable）？

**解答：**

本题的码是 C2 = {1, 101}（见正文 Example 5.5：`1` 是 `101` 的前缀，故 C2 **不是**前缀码 prefix code）。但「不是前缀码」并不等于「不能唯一译码」。唯一可译码的定义（正文式 5.4）是：**不存在两个不同的符号串（symbol strings）x 与 y，使它们编码成同一个二进制串**。我们要判断的就是这个。

**第一步：观察码字结构。** C2 只有两个码字（codeword）`1` 和 `101`，长度分别为 1 和 3。任一合法的编码串都由这两个码字拼接而成，例如

```math
c^+(x) = 101\ 1\ 1\ 101 \dots
```

**第二步：给出一个从左到右的唯一译码规则，并证明它无歧义。**

关键性质：**码字 `101` 只能以「1 开头、紧接着 0 1」这一种方式出现**。因为 `101` 这个三位码字，中间位是 `0`，而码字 `1` 只含一个 `1`。因此：

- 当扫描编码串时，遇到一个 `1`，它有两种可能：
  - (a) 它是独立码字 `1`；
  - (b) 它是 `101` 的第一个符号，此时它后面必须**紧跟 `01`**。
- 而 `0` 只能出现在 `101` 的内部（作为其第二个符号）。单独一个 `0` 不是任何码字，也不是任何码字的前缀。

于是可以采用**从右向左**的判定（这正是 C2 的巧妙之处）。把 C2 的每个码字反转：`1 → 1`，`101 → 101`，得到的码集还是 {1, 101}（自反）。但换一种更直接的说法：

**从右往左读**编码串时，一旦遇到 `1`，看它左边（即更靠近串尾方向）能否构成 `101`：

- 若当前三个符号是 `101`，则它必为一个完整码字 `101`（因为 `01` 不可能由 `1` 开头、也不可能由 `101` 结尾之外的方式产生，`0` 单独不合法，只能是 `101` 的一部分）；
- 若当前符号只是一个孤立的 `1`（其左边不是 `01`），则它必为码字 `1`。

**第三步：证明划分唯一（反证）。** 假设存在两个不同的符号串 `x ≠ y` 满足 `c^+(x) = c^+(y)`。取两者第一个不同的码字位置。在此位置之前 x、y 完全一致；在此位置起，若 x 用 `1` 而 y 用 `101`，那么因为 y 的 `101` 在编码串中留下 `101`，而 x 的 `1` 只留下 `1`，接下来 x 必须用后续码字去「补」出 `01`——但唯一的两个码字都无法产生以 `0` 开头的片段（`1` 和 `101` 都以 `1` 开头）。矛盾。若 x 用 `101` 而 y 用 `1`，同理 y 后续无法解释那串 `01`。因此这种分歧不可能发生。

**第四步：直接举例验证一条有歧义嫌疑的串也能唯一译码。** 例如编码串 `11011`：

```math
11011 = 1\,101\,1 \quad (\text{符号串 } a\,b\,a)
```

有没有别的划分？尝试 `11\ 01\ 1`——但 `11` 不是合法码字（码字只有 `1` 和 `101`）；`1011` 也不是。再尝试 `1\,1\,0\,1\,1`——`0` 不是码字。唯一合法划分就是 `1 | 101 | 1`。所以它唯一译码为 `aba`。

**结论：C2 是唯一可译码的（uniquely decodeable）。**

> <span style="color:#1e8449;">**[note] 「前缀码」与「唯一可译码」的关系：**</span> 前缀码（prefix code）一定是唯一可译码的，但反过来**不成立**——唯一可译码不一定是前缀码。C2 = {1, 101} 正是这个反例：`1` 是 `101` 的前缀，所以 C2 不是前缀码；但它仍然唯一可译码。要记住的唯一可译码充要条件是 **Kraft 不等式**（Kraft inequality）`∑ᵢ 2^(-lᵢ) ≤ 1`（下章定理 5.1/5.2），C2 的码长 (1, 3) 满足 `2^(-1) + 2^(-3) = 1/2 + 1/8 = 5/8 ≤ 1`，故存在唯一可译码。注意：C2 在正文 Example 5.5 之后，作者用同一个「反向」技巧在 Example 5.13 附近证明 C6 唯一可译码，思路与此题完全一致——一个码与它的反向码（reverse code）唯一可译码性等价。

## Exercise 5.16（习题 5.16）　[3, p.105]

**题干原文：** Prove that there is no better symbol code for a source than the Huffman code.

**中文：** 证明：对于一个信源（source）而言，不存在比 Huﬀman 码（Huffman code）更优的符号码（symbol code）。

**解答：**

我们要证明的核心结论是：在**唯一的可译码（uniquely decodable）、且满足前缀性质（prefix condition）**的前提下，Huﬀman 算法构造出的码，其期望码长（expected length）$L = \sum_i p_i l_i$ 在所有符号码中达到最小。也就是说，Huﬀman 码是**最优**（optimal）的。

证明分三步：先证两条引理，再用归纳法完成。

---

**引理 1（最小概率符号在最优码中码字最长）。** 设信源 alphabet 为 $\mathcal{A}_X = \{a_1,\dots,a_I\}$，概率为 $p_1 \ge p_2 \ge \cdots \ge p_I$。在**任意**一个最优前缀码中，若 $p_j > p_k$，则必有 $l_j \le l_k$，即概率更小的符号，其码字（codeword）长度不会更短。

**证明（交换论证 / exchange argument）：** 反设存在最优码 $C$，其中某两个符号满足 $p_j > p_k$ 却 $l_j > l_k$。构造新码 $C'$：把 $a_j$ 与 $a_k$ 的码字互换，其余不变。$C'$ 仍是前缀码（互换码字不破坏前缀性）。两种码的期望长度之差为

```math
L(C') - L(C) = \big(p_j l_k + p_k l_j\big) - \big(p_j l_j + p_k l_k\big)
            = (p_j - p_k)(l_k - l_j).
```

由假设 $p_j - p_k > 0$、$l_k - l_j < 0$，故 $L(C') - L(C) < 0$，即 $L(C') < L(C)$，与 $C$ 最优矛盾。故最优码中必有「概率大 $\Rightarrow$ 码长短」。由此直接推出：**概率最小的符号 $a_I$ 拥有最长的码字**。

---

**引理 2（可找到两个等长的最长码字，且仅末位不同，即互为「兄弟」）。** 在最优前缀码的码树（code tree）中，存在两个码长都等于最大长度 $l_{\max}$ 的码字，它们除最后一位外完全相同。

**证明：** 考虑码树中一条最长路径（深度 $l_{\max}$）所到达的叶子，其对应的码字长度为 $l_{\max}$。若该叶子没有「兄弟」（即其父节点只有一个孩子），则可以把这条边向上收缩一层，把该码字缩短 1 位而仍保持前缀性，从而降低期望长度——与最优性矛盾。因此，每个深度 $l_{\max}$ 的叶子必有其兄弟。特别地，取概率最小的符号 $a_I$（由引理 1 其码长也是 $l_{\max}$），它的兄弟也是一个深度 $l_{\max}$ 的叶子；由引理 1，这个兄弟必是**次小概率**符号 $a_{I-1}$（因为若兄弟概率较大，交换后能降期望长度）。于是 $a_{I-1}$ 与 $a_I$ 的码字等长，且只差最后一位——它们是最优码树里的一对「兄弟」叶子。

---

**归纳步骤（完成证明）。** 设 $I$ 为符号个数。对 $I$ 归纳。

- **归纳假设：** 对任何 $I-1$ 个符号的信源，Huﬀman 算法给出最优码。

- **归纳步：** 给定 $I$ 个符号的信源，取概率最小的两个符号 $a_{I-1}, a_I$。由引理 2，存在一个最优码，使 $a_{I-1}$ 与 $a_I$ 是兄弟叶子，码长同为 $l'$。把这一对兄弟合并成一个新符号 $a'$，概率 $p' = p_{I-1} + p_I$，其码字即去掉这最后一位，码长为 $l'-1$。

  记原码（$I$ 符号）期望长度为 $L_I$，合并后（$I-1$ 符号）码的期望长度为 $L_{I-1}$，则

```math
L_I = L_{I-1} + (p_{I-1} + p_I),
```

  因为这对兄弟各自比合并后的符号多 1 位。反之，任何 $I-1$ 符号码，只要把某个叶子拆成一对兄弟，就得到一个 $I$ 符号码，期望长度增加该叶子的概率。因此，**最小化 $L_I$ 等价于先最小化 $L_{I-1}$ 再拆概率最小的叶子**——这正是 Huﬀman 算法的做法（每一步都合并当前概率最小的两个符号）。由归纳假设，合并后的 $I-1$ 符号最优码由 Huﬀman 给出，故 $I$ 符号的最优码也由 Huﬀman 给出。

  归纳基（$I=2$）：两个符号时，最优码显然是各给 1 位（`0` 与 `1`），与 Huﬀman 一致。

综上，对任意符号个数，Huﬀman 算法得到的码期望长度最小，即**不存在比 Huﬀman 码更优的符号码**。证毕。$\blacksquare$

> <span style="color:#1e8449;">**[note] 最优性的前提：**</span> 上述「最优」是在**符号码 + 前缀条件**框架下定义的（期望长度最短）。Huﬀman 码的最优性用两条引理（最小概率符号码字最长、最优码中总有一对等长的兄弟叶子）把问题化归到 $I-1$ 个符号，正是**贪心（greedy）选择性质 + 最优子结构**的标准体现，也是用交换论证（exchange argument）证贪心最优的经典范例。

## 附：原文中的两道例题（供对照，非习题）

本节原文里还夹有两道 Example，虽非 Exercise，但与本证明直接相关，简要给出结论供交叉验证：

- **Example 5.17**：对英文单字母统计（图 2.1 的 monogram 分布）构造 Huﬀman 码，得到期望长度 **4.15 bit**，而该系综熵为 **4.11 bit**（见原文图 5.6 码表）。可观察到实际码长 $l_i$ 与理想码长 $\log_2(1/p_i)$ 之间的偏差——因为各 $p_i$ 并非 2 的负幂，无法精确等于 $\log_2(1/p_i)$。

- **Example 5.18**：给定理 5.24 的系综
  $\mathcal{A}_X = \{a,b,c,d,e,f,g\}$，$P_X = \{0.01,0.24,0.05,0.20,0.47,0.01,0.02\}$，
  求最优二进制符号码。**贪心自顶向下**（把集合不断拆成尽量等概率的两半）得到的码期望长度 **2.53**；而 **Huﬀman 算法**给出的码期望长度 **1.97**，更短。这正说明：自顶向下的均衡二分**并非**最优，贪心合并（Huﬀman）才是——即 Exercise 5.16 所证结论的一个具体反例演示。
